# FE-07 / U16 — Descarga auditada de documentos para ADMIN
Objetivo: consulta, visualización y descarga segura de documentos vigentes para ADMIN, con lectura aditiva del puerto `AlmacenDocumentos`. Rama `feat/fe07-u16-descarga-admin` (base `main` baba56c). Entrega: cuatro commits locales, un PR posterior (push/PR/merge no autorizados). Runners: Maven/JUnit (`./mvnw -o`, `-Pdb-tests`), Vitest, Playwright E2E reales.

## Specs
- S1 (memoria y concurrencia): «La lectura debe respetar estrictamente el límite máximo de bytes, incluso ante respuestas incompletas o maliciosas de Storage.» «Los permisos del semáforo deben liberarse correctamente ante éxito, errores y desconexiones. No deben liberarse antes de finalizar la entrega del contenido.»
- S2 (integridad): «Verificar el tamaño y SHA-256 completo antes de entregar cualquier byte del documento. Ante un fallo, responder de forma estructurada sin exponer contenido documental.»
- S3 (auditoría): «Mantener el comportamiento fail-closed: si la auditoría obligatoria no puede confirmarse, no se entrega el archivo.» «Documentar que el evento previo a la transmisión acredita la autorización e inicio de entrega, pero no garantiza la recepción completa por parte del cliente.»
- S4 (seguridad): «Mantener los controles de autenticación, MFA, CSRF, autorización por escuela y pertenencia al deportista.» «No introducir modificaciones globales de seguridad para resolver una necesidad específica de este endpoint.»
- S5 (privacidad): «Evitar persistencia intencional de documentos en servidor y frontend. Liberar los recursos temporales correctamente y mantener nombres de archivo neutros.»
- S6 (compatibilidad): «La nueva operación del puerto `AlmacenDocumentos` debe ser aditiva. No modificar el comportamiento de creación, inspección ni compensación.»
- S7 (verificación): matriz de autorización, aislamiento entre escuelas, fallos de integridad y auditoría, límites de memoria y concurrencia, E2E con backend y PostgreSQL reales y dobles externos, regresión completa del pipeline documental; revisión independiente Sonnet 5.5 / High y procedimiento Gentle AI con consentimiento.
- S8 (alcance): «No adelantes U17, U18 ni la corrección del 409 pendiente de U15.» «La carga documental debe permanecer deshabilitada en producción.»
- S9 (decisiones aprobadas): D1 «almacenamiento temporal en memoria acotada, sin archivos en disco»; D2 «cabecera CSRF obligatoria para el GET administrativo de descarga»; D3 «nuevos códigos de error específicos de esta ruta, sin modificar los contratos existentes» (`404 DOCUMENTO_NO_ENCONTRADO`, `409 INTEGRIDAD_NO_VERIFICABLE`, `502 INTEGRIDAD_FALLIDA`, `503 DESCARGA_NO_DISPONIBLE`, `429 DESCARGA_OCUPADA`).
- S10 (plan aprobado): `ContenidoLeido leer(DestinoPreparado destino, long maxBytes)` en el puerto; lectura `GET /object/authenticated/{bucket}/{clave}` reutilizando el `RestClient`, `validarDestino` y `verificarBucketPrivado`; `GET /api/admin/deportistas/{deportistaId}/documentos/{documentoId}/archivo` (ADMIN con MFA, CSRF, escuela + deportista + vigente + operación PUBLICADA; destino solo por `DestinoPreparado.desdeRegistro`); secuencia autorizar → permiso propio → leer → tamaño + SHA → auditoría `DOCUMENTO_DESCARGADO` confirmada → bytes; cabeceras `attachment` con nombre neutro, `nosniff`, `no-store`, `CSP sandbox`; `banfield.documentos.descarga.concurrencia` (2, rango 1–8); sección «Documentos» en la ficha ADMIN con «Ver» (imágenes en memoria, URL revocada) y «Descargar» (PDF explícito); `apiGetBlob` aditivo.
- S11 (detención): «Si aparece un problema que requiera cambiar el alcance o alguna decisión aprobada, presentame las alternativas antes de modificarla.»
